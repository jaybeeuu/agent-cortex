# style-versioning

This repo uses **changesets** for fully automated versioning and publishing. No manual version bumps, no manual releases.

## When to use

Trigger this skill when:
- Completing work that needs a release
- Asking "how do I version this change?"
- Creating a PR that changes shipped behaviour

## The workflow

### For every PR with changes

1. **Make your changes** (code, skills, agents, whatever)
2. **Create a changeset** describing the change:
   ```bash
   pnpm changeset
   ```
   - Choose the bump type: `patch` (fix/clarification), `minor` (new skill/agent/feature), `major` (breaking)
   - Write a short description of what changed
3. **Commit the changeset file** (lives in `.changeset/`) along with your changes
4. **Open a PR**

### After merge to main

The `release.yml` workflow handles everything:

1. **Detects new changesets** on main
2. **Creates or updates a "Version Packages" PR** with bumped versions and updated CHANGELOG
3. **When "Version Packages" is merged**:
   - Bumps `package.json` version
   - Syncs `plugin.json` version (via `scripts/sync-plugin-version.sh`)
   - Updates `CHANGELOG.md`
   - Creates a git tag
   - Publishes to npm via OIDC (no `NPM_TOKEN` needed)
   - Creates a GitHub release automatically

### Version lockstep

All version numbers stay in lockstep automatically:

1. `package.json` → bumped by changesets
2. `plugin.json` → synced by `scripts/sync-plugin-version.sh`
3. `CHANGELOG.md` → generated by changesets

**Never bump versions manually.** Always use `pnpm changeset`.

## Common mistakes

- **Bumping versions manually**: Don't touch `"version"` in `package.json` or `plugin.json` directly. Use `pnpm changeset`.
- **Skipping the changeset**: A PR without a changeset won't trigger a release. The changesets bot will remind you.
- **Wrong bump type**: `patch` for fixes, `minor` for additions, `major` for breakage. When in doubt, ask the user.

## What changed from the old workflow

| Before (manual) | After (changesets) |
|---|---|
| Agent bumps versions locally | `pnpm changeset` creates intent file |
| Manual GitHub release creation | Automated via `release.yml` |
| `publish.yml` triggered by release | `release.yml` triggered by push to main |
| Version sync was manual | `sync-plugin-version.sh` runs automatically |
