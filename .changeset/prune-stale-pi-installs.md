`agent-cortex install pi` now reconciles the trees it owns instead of only ever adding to them. After writing, it removes the copies the source no longer produces — a skill directory dropped upstream, a support file a skill dropped, a generated agent the source retired — so the installed tree stops accumulating copies that look like live skills to the agent reading them. Ownership is evidenced rather than assumed: the run records the paths it wrote in `~/.pi/agent/.agent-cortex-install.json`, agent files are recognised by the provenance line this installer writes above the agent name (which also covers trees installed before the record existed), and files inside a skill the source still ships are the installer's to replace. Both destructive inputs are guarded: a recorded path that is not a plain relative path inside its tree is ignored with a warning, and a tree whose source resolves to nothing while the record lists paths in it is kept whole with a warning, so a degraded checkout cannot wipe a working install. Everything else in the shared trees is left alone — pi-provisioned npm packages, extensions, and skills or agents the user wrote themselves — and a directory is removed only once this prune has emptied it. `--dry-run` lists the planned removals without deleting anything. The future `agent-cortex upgrade` inherits the behaviour by calling the same installer.
